## Como criar o banco

```bash
mysql -u usuario -p < safralink_mysql.sql      # cria o banco safralink e as tabelas
mysql -u usuario -p < safralink_testes.sql     # opcional: dados de teste e relatório das regras
```

No MySQL Workbench: **File › Open SQL Script**, abra o arquivo e execute. O último resultado do `safralink_testes.sql` é um relatório com cada regra marcada como `OK` ou `FALHOU`.

## Como ler as cardinalidades

As cardinalidades estão no formato **(mínimo, máximo)**, lidas do lado de cada entidade: o par ao lado de uma entidade diz de quantas ocorrências do relacionamento ela participa.

> **CONDOMINIO (0,N)** possui **MERCADO (1,1)**: um condomínio possui de zero a N mercados; cada mercado pertence a exatamente um condomínio.

Nos relacionamentos 1:N, a chave estrangeira fica na tabela do lado (1,1) ou (0,1). Os relacionamentos N:N foram transformados em entidades associativas (indicadas entre parênteses).

## Entidades associativas

| Relacionamento N:N | Associativa | Chave primária | Atributos próprios | Por que pertencem à relação |
|---|---|---|---|---|
| MORADOR ↔ UNIDADE_HABITACIONAL | [VINCULO_RESIDENCIAL](#vinculo_residencial) | `id_vinculo` (identificador próprio) | tipo_vinculo, data_inicio, data_fim, id_admin_aprovador, data_aprovacao | Cada linha é um período de residência; a mesma pessoa pode morar, sair e voltar à mesma unidade sem perder o histórico |

| FORNECEDOR ↔ PRODUTO | [FORNECIMENTO](#fornecimento) | `(id_fornecedor, id_produto)` | preco_custo, prazo_entrega_dias, prazo_pagamento_dias | Custos e prazos diferem por fornecedor |

## Regras verificadas fora do CHECK

Regras que envolvem várias linhas ou tabelas não cabem em `CHECK` no MySQL e são verificadas por gatilho ou pela aplicação, na mesma transação. O `safralink_testes.sql` confere todas elas.

| Regra | Onde |
|---|---|
| Períodos do mesmo morador e unidade não se sobrepõem; o aprovador administra o condomínio da unidade | VINCULO_RESIDENCIAL |
| Contrato e mercado do mesmo condomínio; coberturas de um mercado não se sobrepõem | CONTRATO_MERCADO |
| A venda acontece dentro do período de cobertura do contrato que ela registra | VENDA |
| Soma das saídas de um lote ≤ quantidade recebida (saldo nunca negativo) | LOTE / SAIDA_LOTE |
| `qtd_estoque` = soma dos saldos dos lotes do produto no mercado | DISPONIBILIDADE_PRODUTO |
| No máximo 10 reservas ATIVAS por morador; expiração = início + 30 minutos; 3 expirações em 30 dias suspendem por 7 dias | RESERVA / MORADOR |
| Produto com restrição de idade não é reservado nem vendido a menor de 18 anos | RESERVA / VENDA |
| Soma dos estornos aprovados ≤ valor da venda | ESTORNO |
| Soma das liquidações ≤ valor do título; status ABERTA, PARCIAL ou QUITADA conforme a soma | CONTA_PAGAR / COBRANCA |
| `data_admissao` ≤ data atual | FUNCIONARIO |
